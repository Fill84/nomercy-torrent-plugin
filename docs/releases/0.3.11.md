## NoMercy Torrent Downloader — v0.3.11

Two things that were wrong for as long as the plugin was working: the pages
flickered while anything was downloading, and a browser could outlive the server
that started it.

### The pages stopped flickering

No page polls this plugin. It pushes a snapshot when something moves, coalescing
a burst of changes into one message, and the floor between two messages was a
quarter of a second. That floor was chosen for what a message costs the server.

It is not what a message costs. The host that draws a plugin cannot read this
plugin's payload — it draws every plugin, and a payload is this plugin's own
shape — so it treats any message as "something moved" and answers by re-reading
the entire view over HTTP, translations and all.

A download in flight moves its byte count on every tick, so the changes never
stop coming. A quarter of a second meant four complete page reads a second, for
as long as anything was downloading. That is what the flickering was.

One message a second now. The burst still coalesces, the message still carries
the state after the last change in it, and a plugin with nothing happening still
sends nothing at all.

This is half of the fault and it is the half that is ours. The other half is
that the web app replaces the whole page with a spinner while it re-reads, so
each of those reads is a visible blank rather than a redraw — filed as
NoMercy-Entertainment/nomercy-app-web#31. Fewer messages means fewer blanks; it
does not mean none.

### A browser no longer outlives the server

Every tidy-up here runs on the way out: the last tab closing stops the browser,
and disposing the plugin stops it too. Both need a shutdown to happen.

A server that is killed — task manager, a restart that does not wait, a crash —
runs neither. Sixteen browsers were found running on the owner's machine with
the server stopped, each holding its profile and its memory.

On Windows the browser is now started suspended, put in a job object that
terminates its contents when its last handle closes, and then resumed. The
kernel closes that handle however the process ends, so being killed is covered
by the same arrangement as shutting down properly. Starting it suspended matters:
Chrome forks its renderers within milliseconds, and a process put in a job after
it has already forked leaves those children outside it — and they are the ones
holding the memory.

Off Windows there was nothing to arrange. The Xvfb stage runs the browser as a
child of the server, which already dies with it.

### Everything else

Unchanged from 0.3.10. The chain, the naming, the sources and the encode are
exactly as they were. Nothing about what the plugin decides or downloads has
moved.

### Still outstanding, and not ours to fix

Plugin pages are drawn by the web app inside a shell capped at 64rem. The
Downloads table declares nine columns and all nine are sent; only four fit, so
Peers, Seeds, Ratio, Destination and the row's own buttons cannot be reached on
any display. There is no shape this plugin can ask for that means "full width" —
the cap is in the web app, and no version of this plugin can widen it. Filed as
NoMercy-Entertainment/nomercy-app-web#32.
