## NoMercy Torrent Downloader — v0.3.10

Every page is the same shell again. Shows, Queue, Downloads, History, Skipped, Sources and Settings
were drawn in half the width with a dead pane beside them and their last column cut off; only the
dashboard was right.

### What was wrong

Each page tells the client which shell to draw it in. The dashboard asks for the full-width one.
`ListDetail` is half the width with a pane beside it and `Form` is a 40rem column — and every page
here carries the same bar of eight tabs. A page asking for a different shell moves that bar and
everything under it, so the content jumped on every visit and jumped back on the way out.

It was settled on 11 August 2026, deliberately, and undone on the 14th when Shows and Queue were
given `ListDetail` and Settings its `Form` back. Four more pages followed on the 19th. The dashboard
route was never touched, which is why the page reached with **Open** stayed correct while the rest
drifted — and why it shipped that way.

Fourteen declarations across seven views and the route table now say what the dashboard says.

### Why nothing caught it

Every page's layout was asserted only against itself: one test said Settings is a form, another said
Shows is list-detail, and both passed. The fault was never in one page — it was in two of them
disagreeing, and no test looked at that.

`EveryPageIsTheSameShellTests` holds them against each other now: the route table against the
dashboard's route, and every view the plugin really serves against the dashboard's shell.

### The Skipped page opens

It selected every refusal in the history and drew every one. A row is written for each release a
cycle considered and did not take, so a busy library reaches tens of thousands — 65,878 on the
owner's server — and the page took the better part of a minute to open while the client laid out
rows nobody was going to read.

Fifty a page now, newest first, with the count and the way to the pages either side. The page number
rides in the address, so a page can be linked to, reloaded and gone back to. Pruning never answered
this and was not meant to: a fortnight of a busy library is still tens of thousands of rows. What was
missing is a limit.

### Everything else

Unchanged from 0.3.9. The chain, the naming, the sources and the encode are exactly as they were:
this release changes what six pages look like and how one of them reads its rows, and nothing about
what the plugin decides or downloads.
