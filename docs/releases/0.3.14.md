## NoMercy Torrent Downloader — v0.3.14

One line, and the reason nothing downloaded.

### A client with no metadata is not a seed

Before the metadata arrives nobody knows how large a torrent is, and the
announce sent `left = 0` for want of a better number.

Nought is not "unknown" to a tracker. It means **seed** — and a seed is sent no
peers, because a seed has no use for any. So every magnet this plugin took on
announced itself as finished, and every tracker answered it correctly with an
empty peer list and no error at all.

That is what left a download sitting at "fetching metadata" with no peer and no
seed until it timed out, whether the plugin chose it or the owner pasted it in
by hand. Announcing the same info hash to the same tracker with this plugin's
own code answers `seeders 1206, leechers 462` and hands back ten peers: the
swarm was there, the announce worked, and this client had told it we were done.

`left` is now a terabyte while the size is unknown. The number has to be large
as well as non-zero, so that a tracker ranking by how much a peer still needs
does not read a client that knows nothing as one that is nearly finished.

### Two tests that need a way out

The trackers hand back peers for a swarm measured to have them, and the engine
finds somebody in it. Both need a machine that can dial out to arbitrary peer
ports, which neither the CI runner nor a firewalled desktop can, so both run
only under `NOMERCY_SWARM=1`. A red test that says nothing about the code is
worse than no test at all.

### Everything else

Unchanged from 0.3.13.

### What this does not fix

A magnet still does not reach its metadata on a machine measured tonight: the
engine dialled 175 peers of that swarm, nine completed a handshake, and every one
of them was dropped again before it could hand anything over. Announcing works,
dialling works, and a live peer of that swarm answers our extension handshake
with a real `ut_metadata` id — so the fault is in what happens after the
handshake, and it is not this release.

It is written down rather than guessed at: `ConverseAsync` fetches metadata only
while there is none, and a peer that does not supply it falls straight through to
a `finally` that discards it, because there is no session to keep it in yet.
