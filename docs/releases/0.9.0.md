## NoMercy Torrent Downloader — v0.9.0

A wrong episode the plugin delivered is replaced on its own, the challenge solver uses the server's
browser, and the plugin passes the marketplace scan.

### What changed

- **A wrong episode the plugin delivered is replaced on its own.** An episode that came from a release no
  name source names — South Park S29E03's ViETNAM capture, delivered by 0.8.0 — is searched for again by
  release name. Once the real release has downloaded and its video is staged, the old episode's encoded
  files go to the server's recycle area (`.recycled` beside them, where they can be got back) before the
  new one is encoded. The deliveries of 0.8.1 and earlier are checked against the name sources ten a run,
  after the run's own search, so the first run after the update is not held up by the past.
- **The challenge solver drives the browser the server provides.** The plugin no longer downloads and
  hides a Chrome of its own. The server finds an installed Chrome, hides its window, starts it on the
  first page and stops it when the run is over. **The server needs a Chrome installed** (or
  `NOMERCY_CHROME_PATH` set to one); where it has none, every source behind a challenge — 1337x, TorrentBay,
  EZTV, SceneSource and PreDB's search — is off, and the Sources page says so and names them. Nothing the
  marketplace scan refuses is left in the plugin folder.
- **The plugin's database is the server's.** Settings, show switches, downloads and history move into the
  database the server opens for the plugin; an owner's 0.8.1 database comes along on the first start.
- **Downloads are made sparse by the server**, so a download in progress takes only the space it has
  written.
- **A season pack is judged on the episodes it fetches.** A pack is no longer turned down because the whole
  torrent is bigger than the free space when only some of its episodes are wanted. A download that does not
  fit is tried again six hours later rather than never.
- **One instance of this plugin seeds a magnet's metadata to another** on a private torrent, so a second
  machine can download from the first from a hash alone.
- **A plugin unloaded in the middle of a run** leaves nothing behind that the server reports as a fault.

### Not in this version

- The sites behind a challenge are read only where the server has a Chrome. Whether a managed challenge
  clears through the server's browser has not been seen on a server yet; this version is the first that
  can show it.

### Upgrading

Needs a server of **0.1.584 or later**: the browser and the database this version uses are in that
release's plugin contract (ABI 12.5). Install through the plugin catalogue. **The server loads the plugin
disabled** until it is approved once more on its page: the plugin now asks for the browser
(`browser.headless`) and for library write (`libraryWrite`, to recycle a wrong episode's files), and for
the host a challenge is cleared through (`challenges.cloudflare.com`). Grant the library or libraries it may
recycle in; until a library is granted, a replacement waits in the intake folder and the Downloads page
says why. Settings, show switches and downloads carry over into the server's database.
