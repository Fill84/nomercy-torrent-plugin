## NoMercy Torrent Downloader — v0.6.2

What a real server showed on the nights after 0.6.1: a finished download that did not move, files that
stayed in use, a programme taken for another of the same name, and a plugin that deleted what was not its
own. Every fix below has a test that fails without it.

### The plugin deletes only what it created

- In the intake folder, the plugin deletes only a file it staged itself, once nothing waits on it and no
  encode is reading it. A folder in the intake folder is never deleted, and neither is any file the plugin
  did not stage, whatever it is called.
- In the download folder, the plugin deletes the files a torrent of its own names, and a folder those files
  were in once nothing else is left in it.

### A finished download is moved, at once

- A finished torrent that is not seeding is let go of by the client and its video is moved into the intake
  folder. On one disk that is a rename and takes no time; it used to be a byte-by-byte copy that took
  thirty-five minutes for 1.3 GB, and could not take the download away afterwards.
- What else the torrent downloaded, and its folder, are then cleared from the download folder.
- A torrent still seeding is copied and keeps its files, on every system.
- A download that was moved and could not be put in place is put back, and is never deleted.

### Files a torrent held are let go of

- A removed torrent closes its files, so they can be deleted or moved. They used to stay "in use by another
  process" for as long as the server ran.
- A peer that disconnects as the last piece arrives no longer keeps the download from saying it is finished.

### An encode the server skips no longer hangs

- The server says nothing about an encode it skips because every output already exists. A grab now closes
  when the library holds a file named for its episode and the server has not said the encode is running.
- An episode whose file is in the library under its own name is not counted or searched as missing,
  whichever episode the server registered it against.
- A grab whose staged files have all gone is searched for again, unless an encode is said to be running.

### Another programme of the same name is not taken for yours

- A release name dated more than a week before the episode aired is not taken for it. Two programmes called
  Dark Matter — 2015 and 2024 — answer the same search, and the 2015 names are years older.
- The same applies to results from the indexers' own episode search, where the indexer writes an upload
  date: The Pirate Bay, EZTV, Nyaa, TorrentBay, Torrentz2, and 1337x where it writes the year.
- A release name carrying another year than the show's is refused.

### Also

- Stop ends a run from the moment Run is pressed until the run closes, including while it waits on
  downloads and encodes. Downloads already running carry on.
- The client is safe when many peers deliver metadata at once, and an encrypted connection is no longer
  torn by messages sent at the same moment.
- The challenge browser cannot be stopped in the middle of starting, and a server shutdown waits at most a
  few seconds for a browser still starting.

### Upgrading

Nothing to do. Update through the plugin catalogue; settings, show switches and downloads carry over.
