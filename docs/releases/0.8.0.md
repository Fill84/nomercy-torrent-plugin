## NoMercy Torrent Downloader — v0.8.0

Seven reported problems fixed: finished downloads that never reached the intake folder, providers that
failed on Docker, logs too thin to debug with, copies nobody seeds, season packs, and the tables.

### What changed

- **A finished download always reaches the intake folder** (#3). A download that finished while another
  transfers pass was ending could be missed, and a move or copy that failed once was never tried again.
  The plugin now looks again every minute while a finished download waits, and at the start of every
  run. A failed move or copy logs a warning with the path and the reason, once per download.
- **No Xvfb, no failing searches** (#6). On a Linux host without `Xvfb`, such as the server's Docker
  images, the plugin starts no browser. It logs once: "Xvfb is not installed, so sources behind a
  challenge are off." Those sources are skipped, every other source keeps working, and the Sources page
  names the ones that are off. macOS now skips them the same way. NoMercy-Entertainment/nomercy-media-server#597
  asks for `xvfb` in the server images.
- **A log level, and a log file of the plugin's own** (#7). Settings › Advanced has a log level: Error,
  Warning, Information (the default), Debug or Trace. It applies at once. The server lets no plugin line
  below Information through, so every line at the chosen level also goes to
  `logs/torrent-downloader-<date>.log` in the plugin's data folder. One file per day, the last seven kept.
  The page shows the folder. Passkeys, API keys and tracker logins are removed from every line.
- **A copy nobody seeds is not started** (#2). A torrent every indexer lists with 0 seeders is passed
  over for the next copy. If none is seeded, the episode is searched again on the next run, so an
  episode that has only just aired gets its chance. A download missing a piece that no connected peer
  holds for the stall time is stopped as "Cannot complete" and another copy is looked for.
- **A season with several gaps takes a pack** (#1). When two or more aired episodes of one season are
  missing, the season's pack (`Show.S01.…`) is looked for first and judged by the show's settings. Only
  the videos of the missing episodes are downloaded from it. Episodes the pack does not hold are searched
  for one by one on the next run. One missing episode, or no pack found: single episodes, as before.
- **Tabs** (#4). Queue, Activity during a run and the overview with several libraries show one table at a
  time, with a tab per table and its count. The tab is part of the address, so reload and back keep it.
- **Sort, filter and paging** (#5). Every table answers `sort`, `order`, `filter`, `page` and `pageSize`.
  Nothing changes on screen until the web app sends them (NoMercy-Entertainment/nomercy-media-server#593).
- **A download you add by hand is never cancelled** because its show is not switched on.
- Smaller fixes: a save of the settings can no longer be undone by a load running at the same moment, and
  a torrent handed to the client is never left stopped until the next run.

### Upgrading

Install through the plugin catalogue, then restart the server once. The buttons of the copy that was
running stay in place until it does (media-server #60). Nothing needs approving again: the manifest asks
for nothing 0.7.1 did not. Settings, show switches and downloads carry over. The log level starts at
Information.
