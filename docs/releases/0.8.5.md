## NoMercy Torrent Downloader — v0.8.5

No episode is encoded twice, a resumed download finds its peers again, and an update no longer waits on
the copy before it.

### What changed

- **No episode is encoded twice.** An encode is asked for in one place, and it is no longer asked there
  for an episode the library already holds, nor for one another download has an encode running for. The
  one exception is an episode being replaced on purpose. Such a download goes on as though its encode had
  been asked for, and is done once the library has its episodes.
- **A torrent added by hand leaves out what the library holds.** Where the torrent's own name is the name
  of a show in a library — "The Ark (2023) S03 …" — the videos of episodes the library already holds are
  not downloaded. Where its name names no show in a library, everything in it is downloaded, and still
  nothing is encoded twice: of what a finished torrent holds, only the episodes the library lacks and no
  other download is fetching go to the encoder. A torrent holding nothing new is left where it is, and the
  History page says why, once.
- **A resumed download dials at once.** The client dials only when a torrent's pass comes round, and
  between passes it rested for as long as the trackers asked, half an hour as a rule. A pause dropped
  every connection and a resume started nothing, so a download stood with nobody until that rest was
  over. A resume now ends the rest.
- **A download short of peers keeps looking.** With one peer connected the next pass was the trackers'
  whole interval away: a pack came back from a pause with three seeds of fifty-five and stayed there at
  half a megabyte a second. While there is still something to download and room for more peers, the pass
  comes round every minute. The trackers themselves are asked no oftener than they said.
- **The History page shows its table.** Every long reason was written out in full under the table, and
  with seventy of them the table itself was left no height at all. Nothing stands under it now.
- **A download the client gave up on is a line in the history.** One that never got its metadata, or
  stalled until the client let go of it, left the Downloads page and was written down nowhere. It is in
  the history with its release name and the reason.
- **A seeds or peers count says what it is out of.** While no tracker has answered and nobody is
  connected the cell reads "0". Once somebody is connected or a tracker has answered it reads "1 of 1",
  "3 of 55": what is connected, of what the swarm holds. A tracker that answers nought is believed.
- **An update no longer fails on the database the copy before it still holds.** The first start after the
  update to 0.8.4 moved the plugin's database into the server's, and the copy of the plugin the server
  had not let go of yet still held that file, so the plugin's page failed for some minutes. A database
  that cannot be moved is now copied, with everything written to it and not yet folded in.

### What 0.8.4 was

The notes of 0.8.4 said it differed from 0.8.3 only in how seeds and peers are counted. It did not: it
was built from the line that carries everything written up as 0.9.0 — the plugin's database in the
server's, the server's browser for challenges, a wrong episode replaced on its own, plugin contract 12.5
— and it asked for more than 0.8.3 did. Those notes are in `0.9.0.md`; 0.8.5 is that line with the fixes
above.

### Not in this version

- A torrent added by hand whose name names no show in a library still downloads every video in it.
- Why one torrent with a single seed gets no connection is not answered by this version.

### Upgrading

Install through the plugin catalogue. The server keeps running; it is not restarted. The plugin is
loaded again by the update, so a run under way stops and downloads carry on once it is back.

Coming from 0.8.4, nothing needs approving again: the manifest asks for nothing 0.8.4 did not. Coming from
0.8.3 or earlier, the server needs to be **0.1.584 or later** and loads the plugin disabled until it is
approved once more on its page, for the browser (`browser.headless`), library write (`libraryWrite`) and
the host a challenge is cleared through (`challenges.cloudflare.com`). Settings, show switches and
downloads carry over.
