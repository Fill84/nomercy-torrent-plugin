## NoMercy Torrent Downloader — v0.7.0

The plugin loads again on the media server's plugin contract 12.

### Why 0.6.6 stopped loading

The media server renamed its plugin SDK, moved the contract to 12.0, and refuses every plugin built
against anything older — for every plugin, not this one alone. The server log says exactly that:
`Plugin Torrent Downloader failed verification and was marked malfunctioned: ABI '10.0' is incompatible
with server ABI 12.0.` 0.7.0 is built against contract 12 and declares it.

**0.7.0 needs a server on contract 12.** A server on the older contract refuses it the same way round.

### After installing: approve the plugin once more

The manifest now names the encoder, which the server treats as the plugin asking for more than the owner
approved before. The plugin loads disabled until it is approved once more on its page. That is the
server asking, once, and it is the one thing to do after installing.

### What changed underneath

Contract 12 gives a plugin no way into the server's container or its event bus, which is where this
plugin used to reach for a few things. Each has a way of its own now, or is gone:

- **An encode is followed by the job the server named.** The plugin keeps the job id with the grab and,
  while a grab waits on an encode, looks every minute at what the server made of it and at the library;
  the look that finds the episode closes the grab. The answer is better than the events were: a job is
  failed only once the server has truly given it up, with the reason the server wrote, rather than on a
  failure the server was about to retry. A staged file the server is still reading is never swept.
- **A library scan no longer starts a run.** The run interval covers it; Run still starts one at once.
- **A pack added by hand for a show you do not have is left where it is,** and the History names the
  show to add. It was looked up and added for you; the server offers no way to ask for that from a
  plugin now.
- **After an update through the catalogue, press any button twice.** The first press has the server
  serve the updated plugin's buttons and says so; from the second press on everything works without a
  restart. The pages are drawn by the updated plugin from the first fetch.

### Upgrading

Install through the plugin catalogue, then approve the plugin once more on its page. Settings, show
switches and downloads carry over; a grab that was waiting on an encode when the server stopped is
picked up again, and one dispatched by 0.6.6 is closed by the library having its episode, as before.
