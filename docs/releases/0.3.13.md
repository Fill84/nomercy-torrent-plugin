## NoMercy Torrent Downloader — v0.3.13

Downloads that never started, and a magnet the owner pasted by hand that did
nothing at all.

### Every name goes to every indexer before anything is taken

A site only answers about the name it was asked. An indexer holding the release
under a spelling the first name did not use was asked and still never found it,
so its trackers never reached the magnet — and more trackers is the difference
between a download that starts and one that does not. Two Lioness episodes sat at
"fetching metadata" with no peer and no seed for hours while the same release
seeded through trackers published only by a site that had it under another name.

Two early exits are gone: the shelf answer that was taken before a single indexer
was asked, and the return from the name loop the moment one name produced a copy
worth taking. The decision is made once now, over everything every name found.

What has not changed is the cap. `MaxSearchAttempts` still bounds how many names
an episode is looked for under, so the cost is that number times the indexers
rather than every spelling in the pool, and the per-host gate keeps it civil:
every request waits its turn behind that site's own pace, whoever asked for it.
The season and programme shelves are still fetched once a cycle and shared
between every gap of them.

### One hash is one torrent, whatever a site calls it

The info hash is the identity: two rows carrying it are the same bytes in the
same swarm, and a site that writes the year in while another leaves it out has
not found a different file. Merging ran by name only, so rows naming one hash
differently stayed apart and their trackers were never put together — the grab
went out with whichever trackers the row that won happened to publish.

A hash pass now runs after the name pass. After rather than instead: a row with
no hash can only be placed by its name, and that is what the name pass is for.
The merged copy keeps the highest seeder count of every copy and the union of
every tracker, from the listings and from inside every magnet.

### A torrent that failed can be taken on again

0.3.12 made the insert do nothing about a hash already known, which is right
while that grab is open and wrong once it has failed. A failed row stays in the
table and is hidden from the Downloads page, so the owner saw nothing grabbed,
pasted the magnet by hand, and was refused by a row they could not see.

Failed rows are taken on again with whatever the new attempt carries. Done rows
are not: a finished grab has its file in the library, and dragging it back is
what once took the owner's finished grabs from twenty-three to eleven.

### The plugin's own page is a dashboard page

The section a mount names is what the server turns into the address the client
links to, and the plugin never learns its own prefix. Mounted under `library`,
the cog beside this plugin in the dashboard's own list opened it at `/plugins/…`
while the title beside it went to `/dashboard/plugins/…` — two addresses for one
plugin, from one row. It is also what the word means: `settings` is where a
plugin is set up, and this is where it works.

### Everything else

Unchanged from 0.3.12.

### Still outstanding, and not ours to fix

Plugin pages are drawn by the web app inside a shell capped at 64rem, so five of
the Downloads table's nine columns cannot be reached on any display; and a live
push blanks the page rather than swapping the tree. Both are in the web app —
NoMercy-Entertainment/nomercy-app-web#32 and #31.
